A Few Lines About Me

I'm a fourth-year Bachelor of Science in Computer Application student, majoring in Embedded Systems — and somewhere between the first blinking LED and the first sensor that actually reported the room temperature, I stopped seeing microcontrollers as circuitry and started seeing them as quiet, patient collaborators.

What I build lives close to the metal: firmware in C++, real-time operating systems doing their unhurried dance, sensors turning the physical world into numbers a board can reason about. I like the constraint of it. There is no hiding in the embedded world — every clock cycle is honest, every bug is physical, and every fix has to actually fit in the silicon you have, not the silicon you wish you had.

The work is small, slow, and surprisingly alive. A board that notices the room before you do — that, to me, is the whole point of this field.

Projects

BCA182 — FreeRTOS Multisensor Room Monitor

FreeRTOS · C++ · Multisensor · STM32-class · Real-time

A real-time room monitor running on FreeRTOS, juggling several sensors — temperature, humidity, motion, light — under a single scheduler. Each sensor runs as its own task with its own timing and priority, and the trick isn't reading them; the trick is making them cooperate without starving each other.

Role: Firmware design, FreeRTOS task architecture, sensor integration.

What I learned: Task prioritization, mutexes, and the cost of blocking calls inside an RTOS.

Outcome: A stable multi-task monitor that reads several sensors concurrently without dropping cycles.

Personal MP3 Player on STM32 RT-Thread (RT-Spark Dev Board)

STM32 · RT-Thread · RT-Spark · Audio · C++

A personal MP3 player built on the RT-Spark development board, running RT-Thread as the operating system. Audio decoding, file handling, and user input all share one MCU — which means RT-Thread is doing what a good RTOS should: keeping the music playing while everything else politely waits its turn.

Role: Audio pipeline, RT-Thread thread design, storage and playback flow.

What I learned: Real-time audio buffering, thread synchronization, and resource-aware design on constrained hardware.

Outcome: A working portable MP3 player on a single development board.

Lucky 3 — Interactive HMI Game on RT-Thread

RT-Thread · HMI · Interactive · Game · C++

An interactive human-machine interface game running on RT-Thread. Lucky 3 is the project I'm proudest of, because it took embedded systems out of the sensor-and-reading space and into something playful — a game that responds to a human, on a microcontroller, in real time.

Role: Game logic, HMI design, RT-Thread integration.

What I learned: Event-driven UI on an RTOS, responsive input handling, and making hardware feel friendly.

Outcome: A shipped, presentable HMI game — and my first taste of embedded UX.
